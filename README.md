# Reply Style Guard - 短回复防漂移

用于 AstrBot 的群聊短回复风格守卫。

## 为什么需要它

角色机器人刚 reset 时往往能保持“用户一句、AI 一句”的自然短聊；随着历史变长，模型会把自己过去的回复当作风格示例，逐渐出现：

- 一句话能说完却扩成一大段；
- 反复称呼用户/自称；
- 同一个意思换几种说法重复；
- “喵”、波浪号、括号动作等越来越密；
- 解释自己刚说的梗，形成越来越长的自我强化。

本插件用两层方式抑制这种漂移。

## 两层保护

### 1. 每轮临时风格锚点

在 `on_llm_request` 中通过 `extra_user_content_parts + mark_as_temp()` 注入短提示：

- 历史消息只用于理解事实/关系/话题；
- 不把历史 assistant 的回复长度和口癖当作模仿样板；
- 普通闲聊优先一句，最多两句；
- 不解释梗、不重复意思、不堆叠称呼/口癖/动作。

该提示只参与当前请求，不写入会话历史，因此不会自己继续膨胀。

### 2. 普通闲聊硬兜底

如果模型仍然输出过长，`on_llm_response` 会在发送前进行一次确定性缩短：

- 最多保留配置的句数；
- 超过硬字数上限时尽量在自然标点处结束；
- 可去除明显的括号动作描写；
- 不会二次调用 LLM，因此不增加 API 费用和延迟。

以下情况默认**自动跳过硬截短**：

- 用户明确要求“详细、分析、为什么、教程、步骤、代码、报告、写文章……”等；
- 用户消息本身较长；
- Slash 指令；
- 工具调用阶段；
- 代码块回复。

因此它主要管“闲聊越来越啰嗦”，而不是把知识问答也砍成一句话。

## 推荐配置（hina 这类 QQ 群人格机器人）

- 群聊生效：开
- 私聊生效：关
- 每轮风格锚点：开
- 软目标字数：`35~45`
- 最多句数：`1~2`
- 硬兜底：开
- 硬上限：`70~90`
- 去除括号动作：开

如果你想尽量接近“reset 后的极简短聊”，可尝试：

- 软目标 `30`
- 最多句数 `1`
- 硬上限 `60`

## 与 AstrBot 上下文设置搭配

建议同时将 AstrBot 的上下文改为“按对话轮数截断”，例如：

- 压缩前最多保留：10 轮
- 超限一次丢弃：3 轮

插件负责“每轮校正文风”，上下文截断负责“减少旧回复继续当示例”。两者一起更稳。

## 指令

`/style_guard_status`

显示插件是否生效、软/硬字数和当前消息是否会跳过硬截短。

## 注意

- `on_llm_response` 只处理最终 assistant 文本，不处理工具调用结果。
- 流式 chunk 不做硬截短；即便如此，每轮风格锚点仍会生效。
- 如果某些第三方插件在本插件之后再次改写最终消息，可能覆盖硬兜底效果。
